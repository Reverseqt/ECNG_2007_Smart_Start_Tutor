Signed Number Representations

Hardware provides no minus sign, so negative values must be assigned to existing bit patterns. Several conventions for doing so are in use.

Home / Data Representation / Signed Number Representations

Part 1

Sixteen patterns, and now some must be negative

Hardware provides no minus sign. A negative value must be assigned to one of the existing bit patterns.

Four bits admit sixteen patterns. Read as unsigned values these are 0 to 15, and every pattern is accounted for. Representing negative numbers therefore requires that some patterns be reassigned, with a corresponding reduction in the positive range.

The manner of that reassignment is a design decision admitting more than one defensible answer. Three schemes are in common use.

Sign-magnitude

The leftmost bit is a sign: 0 for positive, 1 for negative. The remaining bits are the magnitude, read as an ordinary unsigned number.

value = (−1)s × magnitude

Two's complement

The leftmost column carries a negative weight; every other column is positive as usual.

value = −8b3 + 4b2 + 2b1 + 1b0

Biased (excess-k)

Read the pattern as plain unsigned, then subtract a fixed bias. Nothing is special about any bit.

value = unsigned − bias

Sign-magnitude wastes a pattern

The two highlighted rows are both zero: 0000 is +0 and 1000 is −0. Two patterns, one value. The range shrinks to −7 to +7, and any circuit testing for zero has to check for both.

Two's complement has one zero

Range −8 to +7 — sixteen values for sixteen patterns, nothing wasted. The asymmetry is the price: there is a −8 but no +8.

Biased preserves order

Read the Excess-7 column top to bottom: −7, −6, −5 … ascending all the way. The unsigned column ascends too. Sorting the raw bit patterns sorts the values.

Why IEEE 754 stores a biased exponent

The ordering property is the reason. Because a biased field preserves the order of the values it encodes, two floating-point numbers of the same sign may be compared by comparing their bit patterns as integers, without unpacking. Two's complement does not permit this, since its sequence passes from +7 directly to −8. The biased exponent recurs in IEEE 754 Floating-Point, where an 8-bit exponent field uses a bias of 127 = 27 − 1.

Part 4

Why arithmetic prefers two's complement

Only one of these schemes permits an ordinary adder to handle negative values without special-case logic.

Take (−3) + 5, which should give 2. Encode both operands in a scheme, add the bit patterns with a plain binary adder, discard any carry beyond four bits, and see what comes out.

The consequence is that a processor requires a single adder, rather than an adder together with a separate signed-arithmetic path. This is why two's complement is the integer representation adopted in essentially every machine.
